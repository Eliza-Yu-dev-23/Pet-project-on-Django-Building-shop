# СтройБаза — корпоративный портал строительного магазина

Pet-проект на Django 5 + PostgreSQL: корпоративный сайт строительного магазина
с управлением пользователями, орг структурой и проверкой контрагентов.

Дизайн — UIkit 3, дерево орг структуры — jsTree с ленивой загрузкой.

## Стек

| Слой | Технология |
|---|---|
| Backend | Python 3.11, Django 5.0 |
| БД | PostgreSQL 16 |
| Frontend | Django templates, UIkit 3.17, jQuery + jsTree 3.3 |
| Инфраструктура | Docker, Docker Compose (2 контейнера: `web`, `db`) |

## Быстрый старт

Самый простой способ — запустить `start.ps1` (или двойной клик по `start.cmd`):
скрипт сам запустит Docker Desktop, дождётся движка, соберёт контейнеры
и откроет портал в браузере.

```powershell
.\start.ps1
```

Либо вручную:

```bash
docker compose up -d --build
```

> Важно: перед запуском должен работать **Docker Desktop** (Docker Engine).
> Если он закрыт, команда падает с ошибкой
> `open //./pipe/docker_engine: The system cannot find the file specified` —
> это не ошибка проекта, а не запущенный Docker.

Контейнер `web` сам выполняет миграции и наполнение демо-данными, затем
запускает сервер на <http://localhost:8000>.

Остановить:

```bash
docker compose down
```

Полностью удалить данные PostgreSQL:

```bash
docker compose down -v
```

### Если проект не запускается

1. Проверьте, что Docker Engine доступен: `docker info`. Если команда
   возвращает ошибку — запустите Docker Desktop и дождитесь статуса
   «Engine running» (или используйте `.\start.ps1`).
2. Посмотрите статус и логи контейнеров:

   ```bash
   docker compose ps
   docker compose logs --tail=100 web
   ```

3. Если порт занят (`bind: address already in use`), найдите процесс:

   ```powershell
   netstat -ano | findstr :8000
   ```

   и остановите его либо измените порт в `docker-compose.yml`.
4. Если база осталась в некорректном состоянии после экспериментов,
   пересоздайте её: `docker compose down -v` и снова `docker compose up -d --build`.

## Демо-доступы

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | `admin` | `Admin#2026` |
| Сотрудник | `employee` | `Employee#2026` |

Дополнительно создаются 15 случайных сотрудников. Их сгенерированные пароли
записываются в `demo_credentials.txt` при первом запуске команды `seed_demo`
(файл исключён из git). Администратор может сменить пароль любого сотрудника
через раздел «Пользователи».

## Модули

### 1. Управление пользователями

* 2 роли: `Администратор`, `Сотрудник`.
* 2 предопределённые учётные записи + 15 случайных пользователей.
* Раздел «Пользователи» доступен только администраторам:
  поиск по имени/логину, фильтры по роли, департаменту и активности,
  пагинация, создание и редактирование.
* «Мой личный кабинет» доступен всем: изменение имени и департамента,
  смена пароля с проверкой текущего.
* Неактивный пользователь не может войти, а уже открытая сессия
  принудительно закрывается middleware.

### 2. Орг структура

* 6 департаментов с логичной иерархией:

```
Руководство
├── Финансовый отдел
├── Отдел продаж
│   ├── Отдел строительных материалов
│   └── Отдел инструментов
└── Склад и логистика
```

* У каждого департамента есть руководитель.
* Дерево jsTree загружает узлы лениво через `/org/tree/?id=...`.
* Сначала выводятся департаменты, внутри них — сотрудники.
* При выборе департамента справа показываются руководитель, количество всех
  подчинённых департаментов и сотрудников (включая руководителей дочерних
  подразделений), список прямых сотрудников.
* При выборе сотрудника — его роль, департамент, статус, количество проверок
  контрагентов и департаменты, которыми он руководит.

### 3. Проверка контрагентов

* Поле «Введите ИНН» + кнопка «Проверить», проверка формата и контрольной
  суммы ИНН (10/12 цифр).
* Логика кэширования: если компанию проверяли менее 30 дней назад,
  интеграция не вызывается — показывается последний результат.
* Если прошло больше 30 дней — выполняется запрос к API Checko, создаётся
  запись в истории с текущим пользователем. Нужен ключ `CHECKO_API_KEY`
  (см. `.env.example`).
* При любой ошибке интеграции пользователь видит «Произошла ошибка», а текст
  ошибки сохраняется в БД (`HistoryCheckCounterparty.error_text`) и на сайте не
  показывается.
* В любом случае выводятся последние 6 записей истории по компании.
* Почему выбран Checko, а не Контур.Фокус, и какие данные откуда берутся —
  в [`docs/counterparty_services.md`](docs/counterparty_services.md).

### 4. Авторизация

* Отдельная страница входа с проверкой логина/пароля.
* Деактивированные пользователи не допускаются в систему.
* Защита от открытого редиректа через `next`.

## Схема данных

Соответствует приложенной ER-диаграмме:

```
Role (id, name)
Department (id, name, id_parent, id_boss)
User (id, login, name, password, id_depart, active, hash, id_role)
Counterparty (id, name, inn)
HistoryCheckCounterparty (id, id_counterparty, id_user, date_time, result, error_text)
```

`result` хранит JSON с результатом проверки.

## Хранение паролей: статическая + динамическая соль

Пароль не хранится в открытом виде:

1. В колонке `User.hash` лежит **статическая соль** — случайное значение,
   уникальное для каждого пользователя, заполняется в БД.
2. При установке пароля генерируется **динамическая соль**, которая
   сохраняется рядом с хешем в `User.password`:
   `pbkdf2_sha256$<dynamic_salt>$<digest>`.
3. Хеш = `PBKDF2-SHA256(static_salt + ":" + dynamic_salt + ":" + password,
   120 000 итераций)`.
4. Проверка выполняется через `hmac.compare_digest`, смена пароля
   перегенерирует динамическую соль.

## Разработка с ИИ-агентом

### Про бесплатный Claude

Бесплатный тариф Claude (claude.ai) **не умеет менять файлы на компьютере**:
он работает только в браузере. Claude Code — отдельный инструмент, который
читает и правит проект локально, но в бесплатный тариф он не входит: нужен
Claude Pro (около $20/мес), Max/Ultra или оплата API по токенам.

Можно использовать claude.ai как советчика: он сгенерирует код или патч, но
применять изменения и делать коммиты придётся вручную — это не автоматизация.

Если нужен нулевой бюджет, возьмите агент с локальным доступом и бесплатной
моделью:

| Вариант | Стоимость | Правит файлы и запускает команды |
|---|---|---|
| **OpenCode + бесплатная модель** (уже используется здесь) | 0 | да |
| Gemini CLI | бесплатный лимит Google-аккаунта | да |
| Qwen Code | бесплатный лимит | да |
| Cline / Roo Code в VS Code + бесплатный API-ключ | 0 | да |
| GitHub Copilot Free в VS Code | 0 (лимит запросов) | да, agent mode |
| Claude Code | Pro ~$20/мес или API | да |

### Что уже настроено в проекте

- `AGENTS.md` — правила для агента: как проверять и коммитить изменения.
  Его читают OpenCode, Codex, Cursor и другие агенты.
- `CLAUDE.md` — подключает `AGENTS.md` для Claude Code.
- `scripts/auto_commit.ps1` — коммитит изменения, если они есть; не трогает
  merge/rebase; с флагом `-Push` дополнительно делает `git push`.
- `scripts/watch_commit.ps1` — следит за каталогом и коммитит после 45 секунд
  тишины. Работает с любым агентом и даже при ручном редактировании.
- `.claude/settings.json` — разрешения Claude Code и Stop-hook: когда агент
  заканчивает ответ, автоматически вызывается `auto_commit.ps1`.

### Как это работает

1. Вы пишете указание агенту обычным текстом.
2. Агент правит файлы в каталоге проекта.
3. В конце задачи агент коммитит изменения по инструкции из `AGENTS.md`.
   Дополнительно срабатывает Stop-hook (Claude Code) или watcher.

Запуск watcher в отдельном терминале (необязательно):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\watch_commit.ps1
```

Ручной автокоммит:

```powershell
.\scripts\auto_commit.ps1
.\scripts\auto_commit.ps1 -Message "feat: новая функция"
.\scripts\auto_commit.ps1 -Push
```

### Claude Code: пошагово

1. Оформите Claude Pro или API-ключ.
2. Установите CLI по официальной инструкции
   (`npm install -g @anthropic-ai/claude-code`).
3. Запустите в каталоге проекта: `claude`.
4. При первом запуске подтвердите доверие к папке — тогда применятся
   разрешения и Stop-hook из `.claude/settings.json`.

### Важно

- Автокоммит — страховка, а не замена ревью: проверяйте `git log` и `git diff`.
- Секреты (`.env`, `demo_credentials.txt`) исключены из git.
- По умолчанию автокоммит не делает push, чтобы не зависеть от сети.
  Для автоматического push добавьте `-Push` в аргументы Stop-hook.
