# Инструкции для ИИ-агента

Этот файл читают OpenCode, Codex, Cursor и другие агенты. Claude Code читает
`CLAUDE.md`, который подключает этот файл.

## Проект

Django 5 + PostgreSQL 16, два Docker-контейнера (`web`, `db`).
Подробности, маршруты и доступы — в `README.md`.

## Обязательный workflow

1. Прочитай `README.md` и файлы, которые собираешься менять.
2. Внеси изменения в код.
3. Проверь результат:

   ```bash
   docker compose exec -T web python manage.py check
   docker compose exec -T web python scripts/smoke_test.py
   ```

   Если контейнеры не запущены: `docker compose up -d --build`.

4. Закоммить изменения:

   ```bash
   git add -A
   git commit -m "<тип>: <что сделано>"
   ```

5. Не делай `git push`, force-push и не переписывай историю без явной просьбы.

## Правила

- Не коммить `.env`, `demo_credentials.txt`, пароли, ключи и другие секреты.
- Не удаляй пользовательские файлы и чужие изменения без необходимости.
- При изменении моделей создавай миграцию:
  `docker compose exec -T web python manage.py makemigrations core`.
- При изменении запуска, маршрутов или доступов обновляй `README.md`.
- Соблюдай стиль окружающего кода: шаблоны UIkit, русские подписи, отступы 4 пробела.
- Не оставляй отладочный код, `print()` и закомментированные блоки.

## Формат коммитов

`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:` — короткое описание
в повелительном наклонении, на русском или английском.

Примеры:

- `feat: фильтр по департаменту в списке пользователей`
- `fix: проверка ИНН для 12-значных номеров`
- `docs: описание запуска через start.ps1`

## Автокоммит

В проекте есть `scripts/auto_commit.ps1`: он коммитит только при наличии
изменений и не трогает merge/rebase. Агент всё равно должен делать осмысленный
коммит сам; скрипт и Stop-hook в `.claude/settings.json` — страховка.
